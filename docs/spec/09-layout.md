# 第8章｜ビジュアル主導の版面設計

8-1. 進め方（これまでと変える）

・**仕様を先に書き切らない。** 版面の良否は出力を見なければ判定できず、判定するのは利用者である。本章は判型と比較の観点だけを固定し、版面案は実装して PDF で提示する。
・各案の記述は方針10行程度にとどめる。詰めた仕様は採用案が決まってから書く。
・入力はモックエンジンの決定的な出力に固定する。同じ内容で版面だけを何度も出し直して比較できることが、実モデル接続より先に本章を置く理由（backlog 参照）。
・進行は3回に分ける。(a) 判型の決定（本節まで）、(b) 版面案3本の実装と PDF 出力、(c) 採用案の詰めと残り章への適用。

8-2. 判型：A4横（297×210mm）

現状は A4縦・1カラム流し込み、PowerPoint は 16:9。判型を A4横に統一する。

理由は次の2点に限る。

・**横位置素材に合う。** キービジュアルもムードボードのタイルも横位置が主で、A4縦では表紙でトリミングを強いられるか、上下に余白の出る単調な構成になる。
・**印刷が生き残る。** 16:9 を PDF の判型にすると A4 用紙では上下に帯が出るため、実質「印刷しない前提」になる。日本の広告案件では PDF を刷って回覧する場面が残っており、この選択肢を判型の段階で捨てない。判型は後から取り戻せない側の決定である。

解像度を理由にはしない：16:9 に物理寸法（338mm）を割り当てて ppi を比べるのは誤りで、画面専用の判型なら評価軸はスクリーン画素（1920／2560px）である。その基準では 2K 級の生成画像は 16:9 でも足りる。第7章 7-3 の制約は判型の選択とは独立している。

16:9 との関係：
・**PowerPoint は 16:9 のまま**とし、16:9 は A4横の版面から派生させる。
・そのために**版面は相対座標で定義する**（8-4）。判型ごとに版面を書き分けない。

帰結（(b) で反映する）：
・第7章 7-2 のスロット別必要ピクセル数は A4縦基準のため、A4横の配置幅で置き換える。`ImageSlot.printWidthMm` も同時に更新する（`low-resolution` 警告の判定根拠がここに依存している）。
・PDF レンダラのページサイズと余白、PowerPoint 側のスロット対応を差し替える。

8-3. 比較の観点

版面案は次の3点で比較する。判定は出力された PDF を見て行う。

・**画像の支配度**：表紙・ムードボード・ショットリストで、画像が面のどれだけを占めるか。
・**テキストの従属**：文章が画像に従属して配置されているか（見出しと本文が画像の邪魔をしていないか）。
・**1ページあたりの情報密度**：詰まりすぎ／薄すぎのどちらにも寄っていないか。ページ数は結果として出る。

8-4. 版面定義は相対座標で持つ

・版面（スロットの位置と大きさ、余白、文字サイズの段階）は、判型に対する**比率**で定義する。ミリやポイントの直値を版面定義に書かない。
・レンダラは判型（A4横 297×210mm、16:9 338×190mm 相当）を受け取り、比率を実寸に展開する。これにより 16:9 は A4横の版面からの派生になり、版面定義は1つで済む。
・比率で表せないもの（本文の最小可読サイズ、断ち落としの余白）だけを判型ごとの下限として持つ。
・印刷解像度の判定（第7章 7-2）は展開後の実寸（mm）で行う。`ImageSlot.printWidthMm` は版面定義から導出する値であり、手で並べた定数ではなくなる。

8-5. 版面案（実装済み。判定待ち）

同じ案件データ（モックエンジンの決定的な出力）から3本を出力する。
`npx vitest run --config tools/layout-preview/vitest.config.ts` → dist/layout-preview/*.pdf

A：エディトリアル（12ページ）
・表紙は全面ブリード。画像の上に暗幕を敷き、タイトルは左下に置く。
・章はテキストを版面の左62%に抑え、右側は画像のための余白として空ける。
・ブランド分析・撮影コンセプトなど画像を持つ章は、上42%に画像帯を敷いてから本文へ落とす。
・ムードボードは3×2の大判タイル＋キャプション。1枚あたりの面積が最も大きい。
・ショットリストは横4枚のフィルムストリップで、カットの流れを一列で見せる。仕様は帯の下。
・テキストだけの章はまとめて流し込み、白いだけの面を作らない。
・画像の支配度：中。テキストの従属：明確（行長を抑え、常に画像が先）。密度：中。

B：ギャラリー（9ページ）
・画像を最優先し、テキストはキャプションと短い本文に落とす。余白は最小（3%）。
・ムードボードは4×3の断ち落としグリッド。タイル間の隙間も余白も持たない。
・画像を持つ章は上62%を画像帯にし、本文は帯の下だけで完結させる。
・ショットリストもグリッドで扱い、フィルムストリップは使わない。
・画像の支配度：最大。テキストの従属：強い（説明はほぼ従属物）。密度：低。

C：コンタクトシート（9ページ）
・表紙は上66%が画像、下33%に案件情報。紙面として最も落ち着く配置。
・ムードボードは6×3の小タイルを1ページに収め、全点を一覧できるようにする。
・テキストは2段組。1面あたりの情報量が最も多く、総ページ数は最少。
・ショットリストはグリッド＋仕様の並記。
・画像の支配度：低〜中。テキストの従属：弱い（テキストが面を占める場面がある）。密度：高。

8-6. 実装した規則（実写で確かめたもの）

・**トリミングは上寄せ**：縦にはみ出す分は下から78%削る。中央基準は人物写真で必ず頭が落ちる（表紙・タイル・ストリップの全てで再現した）。スロットごとの指定がある画像は、指定した点を枠の中心に置く（8-7）。
・**枠を伸ばしすぎない**：枠の縦横比の上限は 1.5:1。縦位置素材を横長の枠へ入れると帯になる。上限に当たったぶんは右に残し、左端は動かさない。
・**格子は面の中で一定**：残数で組み直してよいのは面全体の列数だけで、半端な行を広げたり中央に寄せたりしない。左端・列位置・枠の大きさは全ての行で同じ（`gridCells`）。半端な行を中央寄せにすると、同じ面の中に版面が2つできる（実測：上段は左端から385px、下段は中央寄せで515px）。列数は**段数を増やさずに行の欠けが最も少なくなる数**を選ぶ：6枚→3+3、5枚→3+2、4枚→2+2。4枚を3+1にすると最終面の台紙が右三分の二だけ空く。この規則はムードボードだけでなく**フィルムストリップにも同じく当てる**（6カットは4+2ではなく3+3）。
・**枠寸法は章で1つ**：面ごとに残数から出すと、同じ章の同じ枠が面によって大きさを変える（実測：1面目83mm・2面目106mm）。寸法は最初の面の並びで決め、以降の面は枚数が減っても同じ寸法を使う。台紙のほうをタイル群の実寸に合わせて縮める。
・**タイル面には台紙を敷く**：ムードボードのタイル領域のみ、紙色より1〜2段暗いグレージュ。白背景の素材は輪郭が立ち、暗い素材は逆に浮く。台紙は見出しより先に敷く（後から敷くと見出しに重なる）。紙色を落とすと素材1点のために全体のトーンが動くため、地色は変えない。
・**台紙は安全マージンに揃える**：台紙の外周は本文と同じ15mm。半端な位置（版面とも断ち落としとも違う9mm）に置くと、面の中に3本目の基準線ができる。タイルは台紙の内側へ6mm入る。この6mmはタイルの配置幅にも効くので、印刷解像度の判定も同じ値から導く。
・**タイルには一律に枠線**：台紙の上の素材が高明度だと下端が台紙に溶け、枠が揃っていないように読める（実測：枠は同じ高さで揃っていたが、白い素材の下端だけ消えていた）。素材の明暗で処理を変えず、全タイルに同じ細線を引く。
・**本文は2段に釣り合わせる**：1段目だけが埋まって右半分が白く残るのを防ぐため、行数が揃う位置で本文を2段に割る。画像帯の高さは本文の実測から決めるので、面の下部も白いまま残らない。
・**ただし段には下限がある**：どの段も**2項目**に満たない章は2段に割らない（片方に1項目だけ浮くと断片に見える）。判定を行数にすると、1項目が2行に折れただけの段を「足りている」と見なしてしまう。満たない章は1段で組み、測度は全角45字で頭打ちにする（面の幅いっぱいに広げると行が追えなくなる）。
・**dense 面は章の単位で段へ配る**：1段目を満たしてから2段目という順送りだと、4章あっても左段に3章・右段に1章となって右下が大きく空く。逆に量だけで割ると見出しが段末に残るので、割るのは章の境目に限る。章が1つだけの面は本文と同じ段割りの規則（上の下限）に従う。
・**禁則処理**：行頭に小書き仮名・句読点・閉じ括弧・長音符を置かない。行末に開き括弧を置かない。追い出し（直前の字ごと次行へ送る）で処理する。欧文の語は途中で折らない。
・**警告は成果物にも残す**：warn 級は最終面「出力時の注意」に、info 級は同じ面の「提出前チェック」に件数で刻む。同一文は畳む。
・**指摘は面と枠を取り違えない言い方にする**：解像度の不足は**章名**で言う（「キービジュアル」だけだと、同名の枠を持つ表紙を疑わせる）。未登録の件数は**枠の名前**で内訳を出す（「表紙1件」だと、画像の入っている面に未登録があるように読める。実体はロゴ枠）。
・**配置幅は「その面の面付け」から導く**：`slotWidthMm(slotId, 枚数)` が、レンダラが実際に使うのと同じ関数（`pageMetrics`／`tileArea`／`shotArea`／`bandCells`／`cellSize`）から算出する。枠種ごとに単一の定数を返していたときは、同じ枠でも面付けが変われば値が古くなった（実測：実績は147mmと申告して97mmで置き＝誤検知、ムードボードは2列の面でも83mmと申告＝見逃し）。申告値と実配置の一致は、出力した PDF からクリップ矩形を読み出して突き合わせるテストで固定する。
・**同じ IR からは同じバイト列**：PDF の日時は出力時刻ではなく IR の組み立て時刻を使う。出力時刻を入れると同じ版のファイルを突き合わせられない。

8-7. 版面色と切り出し位置

**版面色はブランドのパレットから導く**（`deriveTheme`）。固定値を置くと、テンプレートを差し替えたときに色だけが前の案件のまま残る。導出は明度と彩度で役割を決めるので、パレットの色数や並び順に依存しない。

・紙色＝最も明るい色を白へ寄せる／墨色＝最も暗い色を黒へ寄せる（本文が読める明度差を必ず作る）／差し色＝最も彩度の高い色。
・**台紙＝紙色を1〜2段落として差し色を少量混ぜる。** 紙色と差し色からの相対値なので、紙色を動かすと台紙も一緒に動く。
・IR が theme を持ち、PDF と PowerPoint は同じ値を読む（片方だけ色が古い状態を作らない）。

**切り出し位置はスロット単位で指定できる**（`Workspace.crops`）。同じ画像でも枠の縦横比はスロットごとに違い、残したい部分も変わる（実測：3:2 の横位置を表紙帯へ流すと主題は残るが帽子の天面が切れる）。指定は「画像内のこの点を枠の中心に置く」で、余る側だけが動くため、どの値でも枠に隙間はできない。無指定なら既定の上寄せ。指定は提案書プレビューの各画像から行う。

**目立つスロットの重複は割当側で避ける。** 表紙・ブランド分析・撮影コンセプトはムードボードの取り出し位置をずらす。素材が足りず回り込んだ場合だけ重複するので、そのときは info として提出前チェックに出す。

**検知の対象は表紙・ブランド分析・撮影コンセプト・ショットリスト。** ショットリストはカットごとに別の絵であることが枠の前提で、同じ絵が2カットに出ると併記した仕様（レンズ・構図）と絵が食い違う。ここだけは**同じ枠の中での重複も数える**。

**ムードボードへの再掲だけは重複に数えない（設計上の除外）。** ムードボードは素材の一覧であり、表紙や撮影コンセプトに使った1枚がそこにも出るのは重複ではなく参照元の提示である。文書全体で「同じ画像が2回出ているか」を数えると、正常な構成でも常に発火して、本当の重複が埋もれる。

**枠に載せる項目は選べる。** 供給元が枠数を超えるとき（実績6件に対し枠3つ）、どれを載せるかは提案書ごとに変わる。`Workspace.picks`（スロットID→項目IDの並び）で指定し、既定は供給元の先頭から枠数ぶん。選択は保存されるが**生成物ではない**ので provenance では扱わず、再生成でも保護しない（採用コンセプト・切り出し位置と同じ扱い）。選択が消えた項目を指していれば無視して既定に戻る。

**載らなかった件数は IR が持つ（警告ではなく数値として）。** 枠ごとに「供給元の件数」と「実際に載った数」を IR に持たせ、提出前チェックはその差から作る。警告を積む形だと、積み忘れた経路で「登録したのに出ない」が黙って通る。ただし IR に渡る前に間引く経路（プレビュー用フィクスチャの `grid-6x6` など）は IR からは見えない。IR は受け取った供給元しか数えられないので、**間引きは IR より前で行わない**ことを前提とする。

**枠に載り切らない素材は件数を出す。** 供給元を全点見せる枠（ムードボードのタイル・競合・実績）で枠数を超えた素材は出力に載らない。登録したのに出ないことを黙って起こさないよう、超過分の件数を提出前チェックに刻む。ムードボードのタイル枠は版面の面数から決める（3×2×2面＝12点）。この文で数えているのは**供給元の項目数**（実績ならポートフォリオの件数）であって画像の登録状況ではないため、「登録済み」とは書かない。同じ面に出る「画像未登録◯件」と混ざると、両立しない2文が並ぶ。

**枠が全て未登録の章は、画像の面として組まない。** プレースホルダだけの帯が面の7割を占め、下が白く空く面になる。中身のある枠が1つも無い章はテキストの面として組み直す。ロゴ（供給元が空なら枠ごと出さない）と同じ扱いで、「枠はあるが中身が無い」ときだけ版面が変わるのは不統一だった。

**説明文が無い枠はキャプションを出さない。** 素材のファイル名で埋めると、内部の名前（`08-mood-high`）がそのまま納品物に載る。説明文が無ければ枠の下は出自だけにし、件数を提出前チェックに出す。なお実アプリではタイルと説明文は同じ生成物（`MoodTile`）の属性なので数がずれることはない。ずれるのはプレビュー用フィクスチャのように、素材と説明文を別々に用意した場合だけである。

**キャプションは識別子と出自まで。仕様は本文に置く。** 「Cut 1｜商品単体（正面）」と本文「Cut 1｜商品単体（正面）／100mm macro／…」のように、枠の下と本文で同じ文が二重に出ていた。枠の下は幅が狭く（絵コンテで約58mm）仕様を入れると切れるため、載せる側は本文に決める。キャプションは `Cut 1（持ち込み）`／`LA SÉRÉNITÉ（持ち込み）` の形にし、出自表示だけは落とさない。

**表紙の日付は案件データの提案日**であって、この PDF を作った日ではない。「提案日 2026-08-07」と明示する。出力した時刻は PDF のメタデータ（IR の組み立て時刻）にある。

**画像未登録は info のまま、件数を最終面に出す。** 未登録は「出力が壊れている」ではなく「準備が進んでいない」状態で、案件の初期は大半のスロットが空である。これを warn にすると常時警告が出て、本当に壊れている warn が埋もれる。ただし件数が見えないまま提出されるのは別の問題なので、提出前チェックに件数だけを刻む。

8-8. 出力の2本（何が違うか）

`npx vitest run --config tools/layout-preview/vitest.config.ts` は2本を書き出す。**同じ状態から2本出しているのではない。**

・`adopted.pdf`：`dist/layout-preview/photos/` に置いた**実素材そのまま**。点数は素材の数で決まる。
・`grid-6x6.pdf`：素材を複製・切り詰めて**タイル6点／カット6本ちょうど**に揃えた状態。3+3 と 4+2 の再配分を、素材の点数に左右されずに見るための面であり、登録済みの全素材を出した状態ではない。

8-9. 次にやること

・版面設計の完了時点で実案件を1本通し、クライアントへ出せる品質かを確認して以降の優先順位を見直す。
・競合分析はポジショニングマップ（Competitor が持つ x/y）を面に描く余地がある。画像が無い章のテキスト面は現状ページの1/4しか埋まらない。
・PowerPoint の面付けを A4横の版面から本格的に派生させる（現在共有しているのは判型・余白・文字サイズ・版面色まで）。
・テキストだけの短い章が単独ページになる場合の扱い（ライティングプランが3行で1面を占める）。面をまたぐ前後関係があるため、章の並びを保ったまま詰める方法を別途決める。
