次の実装順：

1. **ビジュアル主導の版面設計**（仕様：第8章 09-layout.md。判型は A4横で確定）。作業範囲は組版の微調整ではなく、画像を主役にした版面の設計。視覚表現の提案書である以上、1カラムの流し込みは提案内容そのものの説得力を損なう。表紙・ムードボード・ショットリストを中心に、画像が支配的な面付けと、テキストがそれに従属するレイアウトを定義する。PDF と PowerPoint の両方に適用し、ブランドカラーのテンプレート差し替えもここに含める。AI生成アセットを表紙全面へ既定で割り当てない規約（第7章 7-3）もここで実装する。
   ・**実モデル接続より先に行う理由**：モックエンジンは決定的なので、同じ内容のまま版面だけを何度も出し直して比較できる。実モデルを先に繋ぐと出力が毎回変わり、版面の良し悪しと生成内容の当たり外れを切り分けられなくなる。版面の評価には固定された入力が要る。
   ・原寸（第7章）が入った直後は、版面を詰める条件が最も揃っている。実寸で置ける画像があって初めて、面付けの判断が現実の解像度に基づく。
   ・**完了時点で実案件を1本通す**。原寸と版面が入れば、モックのままでも提案書として成立する PDF が出るはずである。仕様を積み上げ続ける前に、実際にクライアントへ出せる品質かを一度確かめ、その結果で以降の優先順位を見直す。ここで分かることの例：版面が実案件の情報量に耐えるか、原寸の保存容量が実運用で足りるか、preview 単段（第7章 7-6）で一覧の描画が重くないか、文章の質と体裁のどちらが先にボトルネックになるか。
2. 実モデル接続（GenerationEngine の実装差し替え、設定画面のモデル別名との結線、モデル別の出力解像度の実測と記録（第7章 7-3）、画像生成によるAIアセット登録、失敗時の再試行とレート制御）
